### 3. Аналіз відкритих портів (мінімум 3 порти)

1. **TCP порт 8080:**
   * **Протокол:** TCP
   * **Порт:** `8080` (HTTP-Alternate, тестовий локальний веб-сервер)
   * **Стан:** `LISTEN` (сокет очікує на вхідні підключення клієнтів)

2. **TCP порт 53:**
   * **Протокол:** TCP
   * **Порт:** `53` (DNS — Domain Name System)
   * **Стан:** `LISTEN` (локальний DNS-сервер/резолвер очікує на TCP-запити, які зазвичай використовуються при великих відповідях або zone transfer)

3. **UDP порт 53:**
   * **Протокол:** UDP
   * **Порт:** `53` (DNS — Domain Name System)
   * **Стан:** `UNCONN` (Unconnected — сокет готовий приймати стандартні DNS-запити за протоколом UDP без встановлення постійної сесії)

4. **UDP порт 323:**
   * **Протокол:** UDP
   * **Порт:** `323` (Chrony / NTP — служба точного часу)
   * **Стан:** `UNCONN` (сокет очікує локальних запитів керування службою часу)

---

### 3. Аналіз процесів

1. **Процес 1 (Веб-сервер):**
   * **Рядок виведення:** `tcp LISTEN 0 5 0.0.0.0:8080 0.0.0.0:* users:(("python3",pid=41,fd=3))`
   * **Процес:** `python3` (локальний веб-сервер)
   * **PID:** `41`
   * **Порт:** `8080` (TCP)

2. **Процес 2 (DNS резолвер):**
   * **Рядок виведення:** `tcp LISTEN 0 1000 10.255.255.254:53 0.0.0.0:* users:(("dnsmasq",pid=12,fd=5))`
   * **Процес:** `dnsmasq` (локальний DNS-сервер)
   * **PID:** `12`
   * **Порт:** `53` (TCP) / також відкритий на `53` (UDP)

3. **Процес 3 (Синхронізація часу):**
   * **Рядок виведення:** `udp UNCONN 0 0 127.0.0.1:323 0.0.0.0:* users:(("chronyd",pid=28,fd=5))`
   * **Процес:** `chronyd` (демон NTP/Chrony)
   * **PID:** `28`
   * **Порт:** `323` (UDP)

## Завдання 3. Перевірка TCP-з’єднання (2 бали)

### 1. Виконана команда
```bash
nc -vz google.com 80
```

### 2. Результат виконання команди в терміналі
```text
Connection to google.com (192.178.24.110) 80 port [tcp/http] succeeded!
```
*(У деяких версіях утиліти Netcat: `google.com (192.178.24.110:80) open`)*

---

### 3. Аналіз результату

* **Тип з’єднання:** TCP
* **Порт:** `80` (HTTP)
* **Результат:** **З’єднання встановлено успішно**. Між клієнтом та сервером відбулося повне тристороннє рукостискання (**TCP Three-Way Handshake**: `SYN` → `SYN-ACK` → `ACK`). Віддалений веб-сервер Google слухає порт 80 і відповів готовністю приймати HTTP-запити.

## Завдання 4. Порівняння TCP vs UDP (3 бали)

### 1. Виконані команди
```bash
# Перевірка TCP-з'єднання
nc -vz 8.8.8.8 53

# Перевірка UDP-з'єднання
nc -u -vz 8.8.8.8 53
```

### 2. Результати виконання команд у терміналі

**Для TCP (`nc -vz 8.8.8.8 53`):**
```text
Connection to 8.8.8.8 53 port [tcp/domain] succeeded!
```
*(або `8.8.8.8 (8.8.8.8:53) open`)*

**Для UDP (`nc -u -vz 8.8.8.8 53`):**
```text
Connection to 8.8.8.8 53 port [udp/domain] succeeded!
```
*(або `8.8.8.8 (8.8.8.8:53) open`)*

---

### 3. Порівняння результатів та різниця в поведінці

* **TCP (`nc -vz 8.8.8.8 53`):**
  * **Підтвердження:** Є чітке та гарантоване підтвердження з'єднання.
  * **Поведінка:** Протокол TCP є орієнтованим на з'єднання (*connection-oriented*). Утиліта відправляє пакет `SYN`, отримує від DNS-сервера `SYN-ACK` і відправляє `ACK`. Тільки після успішного встановлення сесії утиліта повідомляє `succeeded`. Якщо порт закритий, сервер відправить пакет `RST`, і утиліта зафіксує помилку відмови у з'єднанні.

* **UDP (`nc -u -vz 8.8.8.8 53`):**
  * **Підтвердження:** Немає гарантії відповіді на транспортному рівні (*connection-less*).
  * **Поведінка:** Протокол UDP не передбачає створення попередньої сесії та підтвердження отримання пакетів. Утиліта просто відправляє UDP-пакет (дейтаграму). Оскільки від сервера не надійшло повідомлення про недоступність порту (ICMP Port Unreachable), утиліта формально фіксує успіх.

* **Головна різниця:**
  * **TCP** встановлює надійну двосторонню сесію зв'язку з попереднім погодженням параметрів і гарантією готовності сервісу.
  * **UDP** не встановлює сесію (працює за принципом «відправив і забув»), тому повідомлення про успіх означає лише відсутність миттєвої помилки маршрутизації або блокування, але не гарантує готовність сервісу обробляти запити.

## Завдання 5. DNS резолвінг (3 бали)

*(За умовами завдання обрано інший домен замість google.com — **`github.com`**)*.

```bash

```
